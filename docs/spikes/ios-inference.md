# Spike: On-Device iOS Gemma LLM Inference

## Overview

This spike evaluates running on-device Gemma models on an iPad (9th generation) to determine the best model and runtime for the voice assistant. The target device is a memory-constrained hardware tier (A13 Bionic, 3 GB RAM).

## Target Device & Environment

- **Device**: iPad (9th generation) (`iPad12,1`, model J181AP)
- **SoC**: Apple A13 Bionic (arm64e / arm64)
- **RAM**: 3 GB total physical memory
- **Operating System**: iPadOS 26.6.2 (build 23G90)
- **Connectivity**: USB wired, paired
- **xcodebuild Destination**: `id=<device UDID>`
- **devicectl Device Identifier**: `<devicectl identifier>`
- **Code Signing**:
  - Development Team: `P6PDV54GBR`
  - Identity: an Apple Development certificate
  - Bundle Identifier: `com.chrishonson.gemmavoice.llmspike`

## Standalone Spike App Architecture (`spikes/ios-llm`)

The spike application is implemented as an independent SwiftUI application in `spikes/ios-llm/`:
- **`Spike.xcodeproj`**: Standalone project with target `Spike`, integrating `google-ai-edge/LiteRT-LM` via Swift Package Manager and linking `CLiteRTLM.framework`.
- **`BenchmarkRunner.swift`**: Automated runner executing immediately on app launch:
  1. Locates the model file inside the app container's `Documents/` directory.
  2. Initializes the `LiteRTLM.Engine` using `.gpu` (Metal) with fallback to `.cpu()`.
  3. Establishes a persistent multi-turn conversation session using the system prompt:
     > *"You are Computer, a concise, friendly voice assistant running fully on this iPad. Keep answers short and conversational. You have no tools, no internet and no way to look anything up or get back to the user later, so never say you will search, check or think about something. Answer right away from what you know, and if you do not know, say so plainly."*
  4. Runs 10 sequential turns:
     - Turn 1: "What is the capital of France?"
     - Turn 2: "Tell me a short joke."
     - Turn 3: "How many legs does a spider have?"
     - Turn 4: "What's a good name for a dog?"
     - Turn 5: "Explain what a battery does in one sentence."
     - Turn 6: "What is seven times eight?"
     - Turn 7: "Give me a tip for sleeping better."
     - Turn 8: "What's the weather like right now?"
     - Turn 9: "Who wrote Romeo and Juliet?"
     - Turn 10: "Thanks, that's all."
  5. Measures per-turn performance:
     - Time to first token (TTFT)
     - Decode throughput (tokens/sec)
     - Resident memory footprint (`task_info` `phys_footprint`)
     - Available memory (`os_proc_available_memory()`)
     - Cumulative peak memory footprint
  6. Executes the Cancel test:
     - Sends "Tell me a long story about a dragon."
     - Triggers `conversation.cancel()` after 1.0 s
     - Measures time until tokens stop streaming
     - Immediately queries "What is two plus two?" to verify whether the session remains functional after cancellation (evaluating the known LiteRT-LM Android cancellation issue)
  7. Emits structured JSON results to stdout prefixed with `SPIKE_RESULT `, flushed immediately via `fflush(stdout)`.

## Results

Both runs used LiteRT-LM 0.18.1 on the GPU (Metal) backend, launched with `devicectl device process launch --console` on 2026-10-31 with the iPad unlocked and plugged in. Raw `SPIKE_RESULT` lines are in `docs/spikes/ios-inference-raw/`.

| Measure | Gemma 3 1B int4 | Gemma 4 E2B |
|---|---|---|
| File size | 557 MB | 2.6 GB |
| Load time | 3.18 s | 1.98 s |
| First token, turn 1 (cold) | 2.51 s | 0.85 s |
| First token, turns 2 to 10 | 0.34 to 0.37 s | 0.38 to 0.45 s |
| Decode speed, average | 16.0 tokens/s | 19.9 tokens/s |
| Peak memory footprint (`phys_footprint`) | 713 MB | 560 MB |
| Lowest available memory (`os_proc_available_memory`) | 1.23 GB | 1.38 GB |
| Turns completed | 10 of 10 | 10 of 10 |
| Meets target (turn 1 under 1.5 s, all 10 turns) | No | Yes |
| Cancel stops tokens within | 0.054 s | 0.018 s |
| Next request after cancel | Fails: `CANCELLED: Task cancelled` | Fails: `CANCELLED: Task cancelled` |

E2B's footprint is lower than 1B's even though its file is about five times bigger. The weights are memory-mapped from the file, so they count as clean file-backed pages, not app memory.

### Increased memory entitlement

The provisioning profile grants `com.apple.developer.kernel.increased-memory-limit` (checked with `security cms -D`). The spike app's own check reports `false` because it searches the binary CMS profile as ASCII text, so that field is wrong. Neither model needed the extra memory.

### Signing

The team is a free personal team: profiles expire after 7 days and the iPad must trust the developer by hand (Settings > General > VPN & Device Management). Uninstalling the last app from that developer removes the trust, so update the spike app by reinstalling over it, never uninstall it.

## Decision

Use **Gemma 4 E2B (`gemma-4-E2B-it.litertlm`, the same file as Android) on LiteRT-LM 0.18.1 with the GPU backend** for iOS.

- It meets the target on the 3 GB iPad: 0.85 s to the first token cold, about 0.4 s after, 20 tokens/s, and stable memory across ten turns.
- It answers correctly and follows the system instruction. Gemma 3 1B got arithmetic wrong and invented the weather.
- One model file and one runtime for both platforms, so the download and prompt rules are shared.

Carry into the iOS engine card (158):
- Cancel leaves the conversation cancelling every later request, the same as on Android. Use the Android fix: after a cancel, start a fresh conversation seeded with the history so far.
- Use the GPU backend. The spike never needed the CPU fallback, but keep it.
